# IT Audit Platform — правила работы для Claude

Общение — по-русски. Соло-разработчик: Рашад.

## Источники правды (не пересказывать, а читать)

- **Задачи: только [docs/backlog.md](docs/backlog.md)** — начинать с блока «▶ СЕЙЧАС». Никаких задач в других местах (в т.ч. сессионные task-списки — запрещены).
- Архитектура: [docs/adr/](docs/adr/) (0001–0018), глоссарий [CONTEXT.md](CONTEXT.md), модель данных [docs/data-model.md](docs/data-model.md).
- Требования клиента: docs/client-answers.md, docs/client-templates/ (RFP + чеклист), docs/vanta-research/.

## Цикл задачи

1. Прочитать задачу в бэклоге, проверить `deps` — заблокированные не начинать.
2. План → код. Перед версткой любого экрана — скилл `ui-ux-pro-max`.
3. Проверка скиллом `/verify` (проектный рецепт: `.claude/skills/verify/SKILL.md`) — реальный запуск, не только тесты.
4. Ритуал завершения — строго по чеклисту «Ритуал ЗАВЕРШЕНИЯ сессии» в backlog.md: `[x]` → блок «СЕЙЧАС» → commit → при необходимости ADR → **готовый промт следующей сессии**.

## Автономный режим

Когда промт говорит «работай автономно» (шаблон E в backlog.md):

- Не задавать вопросов и не ждать подтверждений по обратимым действиям.
- **Декомпозиция эпиков — сам (мандат Рашада 18.07.2026).** Когда расписанные на атомы задачи кончились, а остались эпики (M2/M3, «Добавки», RFP-эпики) — не останавливаться: выбрать следующий по порядку зависимостей эпик и расписать его на атомарные `T-0XX` (стабильные ID, `deps`, DoD) по источникам правды — docs/data-model.md, docs/adr/, docs/vanta-research/gap-analysis.md, CONTEXT.md, — затем делать их как обычные задачи. Выбор эпика/атомов фиксировать в бэклоге; если он вынуждает новое архитектурное решение — писать ADR по ходу (это норма, не повод для `[!]`).
- `[!]` ставить только на НАСТОЯЩИХ развилках: (а) несколько равнозначных архитектурных путей, где выбор меняет продукт и его нельзя вывести из ADR/data-model; (б) нужен ответ клиента (остаток T-001: регулятор, Excel-шаблоны, оплата и т.п.); (в) деструктивное/внешнее действие. Во всех трёх — пометить с причиной и взять следующую незаблокированную; работу вокруг не бросать.
- Лимита задач нет — работать, пока есть незаблокированные задачи ИЛИ нерасписанные эпики. Каждая задача доводится до зелёного чекпоинта (build + verify + бэклог + commit) до перехода к следующей: коммит и есть страховка длинной сессии.
- После суммаризации/сжатия контекста первым делом перечитать docs/backlog.md (блок «СЕЙЧАС») и `git log -5` — источник правды файлы, а не память сессии.
- Задача буксует (2 провала /verify подряд) — пометить `[!]` с причиной и взять следующую незаблокированную; марафон не останавливать.
- Стоп-условие одно: не осталось НИ незаблокированных задач, НИ нерасписанных эпиков (весь backlog `[x]`/`[!]`) — тогда ритуал завершения и промт следующей сессии.
- Запуск марафона — через `/goal <промт E>`: stop-hook не даст сессии завершиться раньше стоп-условия. Для запуска без ручного `/goal` — routine `it-audit-marathon` (cron, см. ниже).

## Технические заметки

- Монорепо pnpm: `apps/api` (NestJS, CJS), `apps/web` (Next.js), `packages/shared` (zod, собирается в dist — сначала `pnpm build`).
- Команды: `pnpm build / lint / typecheck / test / format`; запуск — см. `.claude/skills/verify/SKILL.md`.
- Коммиты: `git add` точечно по своим файлам, если параллельно могла работать другая сессия; сообщения — на русском, `T-0XX: ...`.
