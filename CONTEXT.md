# IT Audit Platform

Multi-tenant платформа для внутреннего IT-аудита групп компаний: engagement'ы с чеклистами, ответы аудируемых, findings с риск-ранжированием и дедлайнами, risk-based планирование аудитов. Термины канонизируются на английском (имена в коде), описания — на русском.

## Language

**Tenant**:
Группа компаний — единица изоляции данных в SaaS. Одна группа = один тенант.
_Avoid_: Organization, Client, Account

**Group**:
Синоним тенанта в доменном смысле: холдинг, объединяющий дочерние компании, с групповым уровнем отчётности.

**Subsidiary**:
Дочерняя компания внутри группы. Объект аудита. Живёт внутри тенанта, не является отдельным тенантом.
_Avoid_: Company, Entity, Branch

**Framework**:
Стандарт или регуляция как верхний контейнер требований (ISO 27001, COBIT, NIST CSF/AI RMF, SOC 2, PCI DSS, местный регулятор…). Группирует контроли; один Control маппится на много Framework'ов (много-ко-многим). Имеет версии (tracked changes при обновлении стандарта). Библиотека фреймворков широкая — паритет с Vanta.
_Avoid_: Standard, Regulation (в UI можно «стандарт», но сущность — Framework), Compliance

**Control**:
Единица курируемой библиотеки: проверяемое требование с формулировкой вопроса и ссылками на пункты фреймворков. Из контролей собираются чеклисты engagement'а.
_Avoid_: Question (вопрос — лишь формулировка контроля), Checkpoint

**Control Library**:
Курируемый каталог контролей, замапленный на стандарты. **Глобальная продуктовая (курируем мы, tenant_id NULL) + адаптации/переопределения тенанта** (ADR-0016). Единственный источник ссылок на стандарты — AI ссылки не генерирует.
_Avoid_: Question bank

**Engagement**:
Аудиторское задание: аудит конкретной дочерней компании (или функции) в заданный период. Содержит чеклист, ответы, findings; проходит жизненный цикл от черновика до выпуска отчёта и follow-up. Режим workflow (формальный/облегчённый) выбирается при создании.
_Avoid_: Audit (аудит — деятельность, engagement — единица работы), Project

**Finding**:
Задокументированное наблюдение аудитора по результатам engagement'а: описание проблемы, риск-ранг, ссылка на контроль/стандарт, **remediation (план/усилие)**, **два владельца — со стороны аудируемого (process/system owner) и со стороны аудит-команды**, дедлайн, дата закрытия. Редактируется/кастомизируется (в т.ч. end user'ом) под audit trail. Может быть standalone (ad-hoc наблюдение аудитора) — связь с Control/Response опциональна. Живёт дольше engagement'а — до устранения. **Закрытие — через повторную проверку (re-test) аудитором, не самодекларацией владельца** (диаграмма RFP, шаг 5).
_Avoid_: Issue, Observation, Deficiency

**Respondent**:
Пользователь со стороны аудируемой компании: отвечает на чеклисты, устраняет findings. Привязан к департаменту/юниту.
_Avoid_: End user, Customer, Auditee (auditee — компания, respondent — человек)

**Test**:
Проверка, дающая доказательство для контроля (Control 1→N Tests): статус, owner, due date, SLA, failing entities. Бывает ручной или автоматической (питается коннектором).
_Avoid_: Check, Evidence (evidence — результат теста, а не сам тест)

**Connector**:
Интеграция с внешней или локальной системой, объявляющая набор capabilities; источник авто-заполнения (доказательства, активы, аккаунты, персонал).
_Avoid_: Integration (как имя сущности используем Connector), Plugin

**Account**:
Идентичность в целевой системе (напр. AWS IAM user, запись в AD), отслеживаемая для access review: owner, groups, type, MFA-статус, status.
_Avoid_: User (User — пользователь платформы, Account — учётка в аудируемой системе), Login

**Role**:
Набор прав с уровнем доступа (No access / View / Edit). Пресеты: Admin, View-only Admin, Editor, Collaborator + аудит-иерархия assessor/manager/approver.
_Avoid_: Group (Group — синоним тенанта), Permission (Permission — атом права, Role — набор)

**Permission**:
Атомарное право = пара (ресурс, действие). Из прав собираются роли (матрица «действие × роль»).

**User**:
Пользователь платформы. **Аутентификация глобальная** (один аккаунт с именем/сертификатами), **доступ к тенанту — через Membership** (роль per-tenant). Две персоны: Auditor и Respondent.
_Avoid_: Account (Account — учётка в аудируемой системе, не в платформе)

**Membership**:
Связь User↔Tenant с ролью/scope (много-ко-многим). Внутренняя команда = membership в одном тенанте; внешняя фирма/MSP = memberships в нескольких (ADR-0015). Приглашение = создание Membership.

**Auditor**:
Пользователь со стороны аудит-команды (роли assessor/manager/approver). Профиль: имя, позиция, департамент, юнит, сертификаты.
_Avoid_: Assessor (assessor — роль Auditor'а, не отдельная сущность)

**Department**:
Организационное подразделение внутри дочки или аудит-команды; к нему привязаны пользователи и владельцы.
_Avoid_: Division

**Unit**:
Более мелкая единица внутри департамента (функция/отдел).
_Avoid_: Team (team — про аудит-команду)

**Response**:
Ответ респондента на пункт чеклиста в engagement'е («вторая колонка» клиента). На его основе формируется Finding.
_Avoid_: Answer

**Document**:
Загруженный файл-доказательство или артефакт, привязанный к контролю/тесту/engagement'у, с owner и сроком актуальности. Evidence = Document или результат Test.
_Avoid_: File, Attachment

**Business Profile**:
Описание бизнес-операций и сегмента дочки (+ загруженные документы), из которого выводится применимый набор Framework'ов и Control'ов.
_Avoid_: Business segment (сегмент — атрибут профиля)

**Business Process**:
Бизнес-процесс из ИТ-«вселенной» (process universe); объект риск-ранжирования и планирования аудита; имеет критичность и **owner (process owner — получает напоминания о дедлайнах)**. **Гибрид: общий каталог на уровне группы + локальные процессы дочки** (ADR-0016). Скоринг критичности учитывает бизнес-природу и исторические данные (в первый год — экспертные веса).
_Avoid_: Function, Workflow

**Asset**:
ИТ-актив/цифровая система (ERP, БД, сеть, приложение…) в реестре активов; ручной ввод + авто-обнаружение коннектором.
_Avoid_: Resource, System (в UI можно «система»)

**Risk**:
Запись риск-реестра: сценарий с inherent/residual оценкой, treatment plan (Mitigate/Transfer/Accept/Avoid), owner, approver. Домены: IT, ИБ, кибербез, IT governance.
_Avoid_: Threat, Issue

**Audit Plan**:
Годовой план IT-аудита: набор запланированных engagement'ов, выведенный из риск-скоринга процессов с учётом capacity команды (человеко-часы, число аудиторов).
_Avoid_: Schedule, Program

**Policy**:
Внутренняя политика с жизненным циклом: версии, срок продления, approver-workflow, attestation сотрудников, маппинг на Framework'и.
_Avoid_: Procedure, Standard

**Vendor**:
Сторонний ИТ-поставщик как объект оценки (TPRM): inherent/residual risk, assessments, категория.
_Avoid_: Supplier, Third party

**Notification**:
Уведомление (email и др.) владельцу/аудитору: назначение finding'а, приближение дедлайна, эскалация. Reminder — периодическое напоминание.
_Avoid_: Alert (Alert — security alert из posture-инструментов)

**Audit Trail**:
Неизменяемый журнал «кто/что/когда изменил» по каждой сущности; версионирование findings и ответов.
_Avoid_: History (в UI — «History»), Log

## Language — RFP Cyberross (ADR-0017, предварительно)

**Audit Type**:
Тип аудита: операционный, финансовый, IT, комплаенс, качество, advisory/расследование. Атрибут engagement'а и плана; определяет шаблоны и отчётность (UNI-06).

**Audit Universe**:
Дерево auditable entities неограниченной глубины (locations, processes, systems, activities) с permanent-файлами на узел. Основа risk-based планирования. Объединяет наши Subsidiary/Process/Asset в общую иерархию.
_Avoid_: Universe (без Audit), Hierarchy

**Working Paper**:
Электронный рабочий документ fieldwork: прямой ввод результатов тестирования, evidence, review notes, sign-off (preparer ≠ reviewer), история «edited since review».
_Avoid_: Workpaper doc, Report (отчёт — выход, WP — процесс)

**Audit Program**:
Набор шагов/процедур аудита по теме, из библиотеки; наполняет audit file (engagement); поддерживает roll-forward год→год.
_Avoid_: Program (перегружено), Procedure

**Time Entry**:
Запись времени аудитора: по аудиту/фазе/программе или непродуктивное время; основа утилизации, бюджета vs факт (TIME-01, UNI-07).
_Avoid_: Timesheet (timesheet — представление, entry — запись)

**Custom Field**:
Настраиваемое бизнес-администратором поле (metadata) на любом уровне working papers/сущностей, без программирования (GEN-07). Крючок в ERD с фазы 1.

## Language — паритет M2/M3 (предварительно)

Термины из разделов Vanta, которые строим по решению о паритете, но в фазах M2/M3. Определения предварительные — финализируются при декомпозиции соответствующих эпиков.

**Access Review**:
Периодическая проверка прав доступа (UAR): кто к каким Account'ам/системам имеет доступ; тип engagement/контроля (ADR-0012). Порождает findings.

**Vulnerability**:
Уязвимость актива из сканера, с severity и SLA-ремедиацией (эпик EP-VULN).

**Change**:
Изменение в кодовой базе/системе (смерженный PR) как объект change management-контроля (EP-VULN/ITGC).

**Device**:
Endpoint-устройство сотрудника (через MDM) с проверками пароль/шифрование/антивирус/блокировка (EP-PERS).
_Avoid_: Computer (в UI — «Computer»)

**Security Alert**:
Алерт от posture-инструмента (CSPM) с окном резолюции (EP-VULN).
_Avoid_: Notification (Notification — уведомление пользователю платформы)

**Processing Activity**:
Запись обработки перс. данных (ROPA) для приватности/DPIA (эпик EP-PRIV).

**Questionnaire**:
Входящий security-опросник, на который AI отвечает из базы знаний (эпик EP-QA). Отличается от нашего checklist (Control) — там мы задаём вопросы, здесь на них отвечаем.

**Commitment**:
Контрактное обязательство перед клиентом (сроки уведомлений об инцидентах и т.п.), синк из контрактов (EP-MISC).

**Trust Center**:
Публичная страница security-posture с запросом документов под access-control (эпик EP-TRUST).
