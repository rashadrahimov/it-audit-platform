# Аутентификация в MVP: локальные аккаунты + TOTP MFA + OIDC + SAML + LDAP

_Обновлено 17.07.2026 по ответам клиента ([[client-answers]]): on-prem клиенты используют локальный Active Directory, поэтому SAML/LDAP перенесены из фазы 2 в MVP._

MVP поддерживает: локальные аккаунты (пароль + TOTP MFA), invite-flow по email (инвайт → подтверждение почты → создание аккаунта) и SSO двумя путями в зависимости от типа поставки:
- **SaaS-клиенты** → **OIDC** (Entra ID / Azure AD, Google Workspace).
- **On-prem клиенты** → **SAML/ADFS + LDAP-федерация** к локальному Active Directory.

Auth-слой проектируется как провайдер-агностичный: набор стратегий (local, oidc, saml, ldap) за единым интерфейсом, включаемых по конфигурации тенанта/инсталляции. Встраивание готового IdP (Keycloak) в поставку не обязательно, но архитектура не должна это закрывать. MFA (TOTP) применяется к локальным аккаунтам; для SSO — на стороне IdP.
