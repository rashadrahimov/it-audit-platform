# Access Review / IAM как первоклассная сущность

User Access Review (кто к чему имеет доступ) — один из самых частых предметов IT-аудита, поэтому моделируется как ядро, а не смежность. Вводится сущность **Account** — идентичность в целевой системе (напр. AWS IAM user, запись в AD), с полями owner, groups, type, status, **MFA-статус**, даты создания/деактивации. Аккаунты импортируются коннекторами ([[0011-integrations-framework]]) либо заводятся вручную.

Поверх аккаунтов — **Access Review** как отдельный тип engagement/контроля (периодический UAR), плюс **access requests** (запрос доступа, в т.ч. JIT) и **deprovisioning tasks** (задачи на отзыв доступа уволенных).

Следствие: IAM-домен встроен в общую модель Control→Test→Finding — access review порождает findings так же, как обычный аудит, а аккаунты без owner или без MFA автоматически становятся кандидатами в failing entities автотестов.
