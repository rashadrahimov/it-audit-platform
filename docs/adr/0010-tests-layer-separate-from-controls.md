# Слой Tests отделён от Controls (continuous compliance)

Между требованием (Control) и доказательством вводится отдельная сущность **Test** (проверка): Control 1→N Tests. У каждого Test — статус, owner, due date, SLA и «failing entities» (объекты, не прошедшие проверку). Тесты бывают ручными и автоматическими: автоматические питаются коннекторами ([[0011-integrations-framework]]) и непрерывно сверяют состояние систем с контролем, ручные закрываются человеком с приложением доказательства.

Причина: исходное ТЗ клиента собирало доказательства ТОЛЬКО вручную через ответы респондентов (point-in-time аудит), тогда как ключевая ценность референс-платформы (Vanta) — continuous compliance с автопроверками. Разделение «требование vs проверка» — не ретрофитится, поэтому фиксируется до модели данных.

Следствия: Evidence — это результат Test (или приложенный Document), а не свойство Control; движок аудита получает два режима — engagement-based (периодический аудит командой) и continuous (автотесты), поверх одной модели Control→Test→Evidence.
