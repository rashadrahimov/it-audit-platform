# Общая БД с изоляцией тенантов через Postgres RLS

Тенант = группа компаний; дочерние компании — сущности внутри тенанта (групповой уровень должен агрегировать по дочкам, поэтому они не могут быть отдельными тенантами). В SaaS все тенанты живут в одной схеме Postgres с `tenant_id` в каждой таблице; изоляция принудительно обеспечивается Row-Level Security на уровне СУБД, а не только фильтрами в коде приложения — баг в коде не приводит к утечке между группами. Рассмотренные альтернативы (схема на группу, БД на группу) отвергнуты как операционно дорогие при малом числе тенантов на старте; on-prem инсталляция — тот же код с единственным тенантом.
