# Ответы клиента (T-001)

Зафиксировано 17.07.2026 в ходе работы с Рашадом. Часть — решения/оценки Рашада, часть — то, что нужно уточнить у заказчика.

## Деплой и аутентификация
- **Деплой**: оба варианта. Клиенты-регуляты берут **on-prem**, остальные — **SaaS** (подтверждает ADR-0002).
- **Каталог/SSO**: для on-prem клиентов — **локальный Active Directory** → нужны **SAML/ADFS + LDAP уже в MVP**. Для SaaS клиентов — **Entra ID/Azure AD → OIDC**. Значит auth-слой MVP = локальные аккаунты + TOTP MFA + OIDC + SAML + LDAP (обновляет ADR-0006).

## Стандарты и язык
- **Стандарты аудита**: ISO 27001, COBIT, NIST CSF / NIST AI RMF, местный регулятор. → библиотеку фреймворков наполняем этими первыми. **Местный регулятор = CBAR (Центробанк Азербайджана)** — найден в чеклисте клиента (контроль IR-02) и подтверждён спецификацией. В спеке также фигурируют COSO, IIA, PCI DSS, SOX/ITGC, GDPR, SOC 2, SWIFT CSP, OWASP. **✅ CBAR засеян в глобальную библиотеку фреймворков (T-C01, seed.ts): «CBAR IT Audit» v1.0, 16 требований по доменам IT-аудита из клиентского чеклиста, трилингвально EN/AZ/RU.** Гейт «местный регулятор» из T-001 закрыт.
- **Язык отчётов**: английский + азербайджанский. (UI остаётся EN/AZ/RU по ADR-0009; отчёты — EN/AZ.)
- **Форматы экспорта отчёта**: PDF + Word (.docx) + Excel (.xlsx) — все три.

## Размер и лицензирование
- **Число дочерних компаний**: произвольное (настраиваемое). **Лицензия считается по количеству дочек.**
- **Размер аудит-команды**: произвольный (настраиваемый). **Лицензия считается и по размеру команды.**
- → Модель лицензирования: **per-subsidiary + per-audit-seat**. Заложить сущности лицензии/квот и метринг. Оформить отдельным ADR.
